# 「ブランチ」タブの設計

Session Desk に 3 つ目のタブ「ブランチ」を足す。セッションのリポジトリにあるブランチを一覧し、選んだブランチが「何を済ませ、次に何をするか」を、日時つきの縦の時系列で見せる。

## 1. 目的と理由

**作る理由**: 作者は、ブランチがいくつあり、それぞれが編集中なのか、commit 済みなのか、push 済みなのか、PR 待ちなのかを、コマンドを打たずに見たい。git-flow.md が定める段階のうち、どこまで進んだかを、Claude が作業するそばで確認できるようにする。

**使う人**: 作者本人（Claude Code と GitHub Flow で、1 人で開発する人）。

**使う場面**: Claude が編集・commit・push をしている最中に、サイドパネルを横目で見て、いまの状態と次の一手を知る。

## 2. 決まったこと（作者が決めた）

| 項目 | 決定 |
|---|---|
| 置き場所 | Session Desk のサイドパネルに、3 つ目のタブとして足す。タブの順は、定型文・履歴・ブランチ。名前は「ブランチ」（仮） |
| 見せ方 | ブランチの一覧と、選んだブランチの経過（縦の時系列）。作者が選んだ案は「左に一覧、右に経過」。端末のパネルは幅が狭いため、並べ方は 5 章のとおり、幅に応じて変える |
| 経過の内容 | 済んだ段階に日時、次にやる段階を目立たせ、その先を薄く見せる |
| 対象 | いま開いているセッションの作業フォルダのリポジトリ 1 つだけ |
| 更新 | 勝手に更新する。更新ボタンを押させない |
| GitHub の情報 | PR の有無・状態、レビューの状態、マージ済みかどうかも出す |
| 名前が規則外のブランチ | 種類を「その他」にして、全部出す |

## 3. ゴール・ノンゴール・アンチゴール

**ゴール**
- ブランチの本数（見出しに「ブランチ 7」のように出す）と、各ブランチの種類（feat・fix・docs・chore・その他）が、一目で分かる。
- 選んだブランチについて、済んだ段階と日時、次の一手が分かる。
- Claude が git を操作した直後に、表示が自動で変わる。

**ノンゴール**
- パネルから git・gh の書き込み操作（push・PR 作成・マージ・ブランチ削除）をしない。表示だけにする。
  - 例外（のちに追加）: 「今」が commit・push・PR 作成・ブランチ削除のとき、パネルの yes/no から Claude に依頼を送れる。パネル自身は git・gh を書き込まない。実行するのは Claude で、削除だけ確認が 2 段になる。マージは対象外。
- 複数リポジトリの横断表示をしない。
- リリース（タグ・GitHub Release）の状態を出さない（作者の指定がないため、第一版の対象外とした。私の判断）。
- CI の結果、マージ競合、マージできるかどうかを出さない。
- GitHub 以外のホスト（GitLab など）の PR を扱わない。
- 別の worktree で checkout 中のブランチの未 commit の変更は見ない（そのブランチの「編集」は、commit の有無だけで判定する）。

**アンチゴール（動いても失敗とみなすもの）**
- 表示のために、Claude の応答や作業が遅くなる。Claude 自身の git 操作を失敗させる（`index.lock` の奪い合い）。
- 手元の git の状態を書き換える（`git fetch` を含む。最新の origin を取りに行かない）。
- 一覧のブランチ数が、実際の `git branch` と食い違う。
- 取れなかった情報を、「済」や「なし」のように見せる。取れなかったときは「不明」と書く。
- 古い情報を、最新のように見せる（鮮度は 5 章の最終行に出す）。

## 4. 段階の定義

### 4.1 対象と比較の基準

- 種類は、feat・fix・docs・chore・その他・既定の 6 つ。
- 一覧の対象は、ローカルブランチ（`refs/heads`）。origin にだけあるブランチは出さない。
- 既定ブランチは、`origin/HEAD` が指すブランチ。なければ main、master の順（git-flow.md と同じ）。決められないときは、2〜4 段階目を「不明」にする。
- 既定ブランチは、種類を「既定」とし、経過を出さない。ただし、既定ブランチ上に未 commit の変更や未 push の commit があるときは、一覧の下に警告を 1 行出す（「切らない」を選んだセッションで気づけるようにするため）。
- 差分と commit 件数は、`origin/<既定ブランチ>` と比べる（PR の比較先が origin 側のため）。ない場合はローカルの既定ブランチと比べる。「進んだ commit」は、既定ブランチにないブランチ側の commit（`origin/<既定>..<ブランチ>`）の数とする。

### 4.2 段階ごとの状態

段階は 8 つ（git-flow.md の 9 段階からリリースを除く）。各段階の状態は、「済」「未」「不明」「省略」のどれか。

| 段階 | 「済」の条件 | 日時の出どころ |
|---|---|---|
| 1 ブランチを切る | ブランチがある（常に済） | ブランチ作成の記録（reflog）。なければ「—」 |
| 2 編集 | 進んだ commit がある、または未 commit の変更がある | 進んだ commit があれば最初の commit の日時。未 commit の変更だけなら「—」 |
| 3 commit | 進んだ commit があり、未 commit の変更がない | 最新の commit の日時と件数 |
| 4 push | origin に同名のブランチがあり、ローカルの commit がすべて入っている | origin 側の記録（reflog）の更新時刻。なければ「—」 |
| 5 PR | 採用した PR（4.4）があり、CLOSED でない | PR の作成日時 |
| 6 レビュー | reviewDecision が APPROVED | 最新レビューの日時 |
| 7 マージ | 採用した PR が MERGED | マージ日時 |
| 8 削除 | 「済」にならない（済になるとブランチが消えるため）。PR が MERGED のときだけ「今」（次: ブランチを削除） | — |

- 未 commit の変更は、いまチェックアウトしているブランチだけで見る。
- detached HEAD のときは、一覧の下に「HEAD は分離状態」と 1 行出す。commit が 1 件もないリポジトリでは「commit がまだありません」と出す。

### 4.3 「今」の決め方

- 「今」は、「済」「不明」「省略」のいずれでもない、最初の段階とする。
- 未 commit の変更があるブランチは、一覧の「今」の表示を「編集中」にする（段階 3 が「今」になる）。
- 済と今が飛び飛びになることがある（例: push と PR が済のあとで、また編集して、3 が「今」）。表示は、段階の順に並べ、各段階に自分の状態をそのまま付ける。
- PR が MERGED のときは、1〜7 をすべて「済」とする。squash マージや rebase マージのあとに、差分や commit 件数が食い違っても、PR の状態を優先する。「今」は 8（削除）になる。
- ただし、未 commit の変更があるときは、MERGED でも段階 3 を「未」にする。「今」は「編集中」にする（変更が残ったままブランチを消さないため）。この規則は、MERGED の規則より優先する。未 commit の変更には、未追跡のファイルも数える。
- 5〜7 のどれかが「不明」のときは、8 も「不明」にする。「不明」を飛ばした結果、「今」にできる段階がないときは、「今: PR 以降は不明」と書く。
- 2〜4 段階目が「不明」（既定ブランチを決められないとき）のときは、「今: 判定できない」と書く。
- 一覧の全行に「今」を出す。選択外の行も、この章の規則で決める。

### 4.4 PR の採り方

- PR は、リポジトリ全体の一覧を 1 回で取り、ブランチ名（`headRefName`）で突き合わせる。fork からの PR（`isCrossRepository` が真）は使わない。
- 同じブランチから PR が複数あるときは、OPEN の PR を採る。OPEN がなければ、作成日時が最新の PR を採る。
- MERGED と CLOSED の PR は、PR の先頭の commit（`headRefOid`）がローカルの先頭と一致するか、ローカルの先頭がその祖先であるときだけ採る。そうでなければ「PR なし」とする（同じ名前でブランチを切り直した場合に、古いマージ済みの PR を拾わないため）。祖先かどうかの確認は、MERGED・CLOSED の PR を持つブランチだけに行う。`headRefOid` がローカルになくて確認できないときは、「PR なし」ではなく「不明」とする。
- 一覧の取得件数の上限に達した場合、一覧にないブランチの PR は「なし」ではなく「不明」とする。選択中のブランチだけは、`gh pr list --head <名前>` で引き直す。

| 採用した PR | 5 PR | 6 レビュー | 7 マージ |
|---|---|---|---|
| なし | 未 | 未 | 未 |
| OPEN、草稿（draft） | 済 | 未（次: 草稿を解除する） | 未 |
| OPEN、reviewDecision が REVIEW_REQUIRED | 済 | 未（次: レビューを待つ） | 未 |
| OPEN、reviewDecision が CHANGES_REQUESTED | 済 | 未（次: 指摘を直す） | 未 |
| OPEN、reviewDecision が空 | 済 | 省略（レビューの設定がない。1 人開発の通常の流れ） | 未（マージ待ち） |
| OPEN、APPROVED | 済 | 済 | 未（マージ待ち） |
| MERGED | 済 | 済 | 済 |
| CLOSED（マージせずに閉じた） | 未（PR が閉じられた。作り直す） | 未 | 未 |

## 5. 画面

- 見出しに、ブランチの本数を出す。
- ブランチ一覧の 1 行に、種類のラベル、ブランチ名、「今」の段階の名前を出す。いまチェックアウトしているブランチに印を付ける。
- 最初に選ばれているのは、いまチェックアウトしているブランチ。
- ブランチを選ぶと、その経過が縦に並ぶ。「済」は日時つき、「今」は目立つ色と「次: ○○」、「未」は薄く出す。
- 種類のラベルは、ブランチ名の接頭辞（`feat/` `fix/` `docs/` `chore/`）で決める。ほかの名前は「その他」。
- 画面は端末に文字で描く。色だけで区別せず、記号（済 ✓、今 ●、未 ○、不明 ?、省略 －）も併用する。
- 幅が狭いときは、上に一覧、下に経過を並べる。幅が十分あるときは、左に一覧、右に経過を並べる（私の判断。幅の境目は作り手が決める）。
- 最終行に、鮮度を出す（例: `git 12:03:10 / gh 12:02:40 時点`）。
- 選んだブランチがなくなったときは、選択を外す。
- ブランチ名・PR のタイトルなど、外から来る文字は、既存の `stripControl` を通して出す。`git`・`gh` の標準エラーは、そのまま画面に出さない。

## 6. 情報の取り方と更新

### 6.1 コマンドの使い方

- git は `$.process.run(["git", "--no-optional-locks", …])` で、GitHub の情報は `$.process.run(["gh", …])` で取る。シェルは使わない。読み取りの操作だけを使う。`--no-optional-locks` は必須（Claude 自身の `git add`・`git commit` と `index.lock` を奪い合わないため）。
- プロセスの数は、できるだけブランチの本数に比例させない。ブランチの一覧は `git for-each-ref`（進んだ commit 数は `%(ahead-behind:…)`、push の状況は `%(upstream:track)` など。使えない git では作り手が代わりの方法を選ぶ）、未 commit の変更は `git status --porcelain=v1 -z` の 1 回で取る。ブランチごとに問い合わせるのは、一覧の「今」に必要な分（MERGED・CLOSED の PR を持つブランチの祖先の確認）に限る。reflog など、日時のための問い合わせは、選択中のブランチだけに行う。1 回の更新でブランチごとに起動するプロセスは、30 本までとする。超えた分は「不明」にする。
- ブランチ名を引数に渡すときは、`refs/heads/` を付けた完全な名前にする。出力は、引用符で包まれない形式で取り、改行は `\r\n` も受ける。
- PR は `gh pr list --state all --limit 200 --json number,state,isDraft,reviewDecision,createdAt,mergedAt,headRefName,headRefOid,isCrossRepository,latestReviews` を 1 回呼ぶ（項目名は作り手が `gh` で確かめる）。fork からの PR は、`isCrossRepository` で除く。
- `gh` の起動失敗（reject）も、終了コードが 0 以外も、通信の失敗も、5〜7 段階目を「不明」にする。origin の URL の判定は、別に行わない（`gh` の失敗に任せる）。
- 呼び出しごとに `timeoutMs` を指定する（目安は 15 秒）。実行中の更新があるときに次のきっかけが来たら、実行中のものが終わったあとに、もう 1 回だけ更新する（commit の直後の変更を取りこぼさないため）。`gh` が失敗したときは、更新の間隔を延ばす。
- 出力が切り捨てられたとき（`isStdoutTruncated`）は、その情報を「不明」にする。
- 次の状態は、タブに短く分けて出す: Git のリポジトリではない、commit がまだない、リポジトリの所有者が違う（`dubious ownership`）、取得が時間切れ。

### 6.2 更新のきっかけ

- 更新は、「ブランチ」タブが表示されているときだけ行う（パネルが開いていて、画面に置かれていること。`$.ui.panes()` の `isPlaced` で確かめる）。タブを開いた瞬間に 1 回更新する。
- きっかけは 2 つ。(1) `tool.call` フックで `await next(e)` が済んだあと（ツールの実行後）に、応答を待たせず（`void`）更新を起動する。ツールが失敗して `next` が拒否されたときも、更新を起動してから、例外をそのまま投げ直す。対象は Bash・Edit・Write に絞る。フックが返ったあとも `$` が使えるかは未検証（作り手が確かめる。使えなければ、(2) の間隔だけに頼る）。(2) 一定間隔（`$.clock.every`）。
- `tool.call` の更新で更新するのは git だけ。ただし、Bash のコマンドに `gh` または `git push` を含むときは、`gh` も更新する（PR を作った直後に反映するため）。
- 間隔の目安は、git が 10 秒、`gh` が 60 秒。ツール実行後の更新は、前回から 2 秒以内なら 1 回にまとめる（私の判断。作り手が調整してよい）。
- タイマーは 1 本だけ持つ。再読み込みや `session.start` の再発火で、二重に作らない。
- 更新のたびに `$.session.cwd()` を読み直す。作業フォルダが変わったときは、前のフォルダの結果を捨てる。
- 取得中に画面を固めない。前回の結果を表示したまま、裏で更新する。

## 7. 制約

- 既存の作りに合わせる。状態は atom に持ち、`Tab` 型は `types/index.d.ts` に足す。段階の判定、ブランチ名の分類、出力の解析は、`hooks/lib.ts` の純粋な関数にして、テストする。git・gh を呼ぶ部分は 1 か所にまとめる。
- 動作確認は `claude plugin test` と、既存の `test-kit.tsx` を使ったテストで行う。git・gh を呼ぶ部分は、テストで差し替える。`claude plugin test` で `$.process.run` を差し替えられるかは未検証。差し替えられなければ、解析と判定の純粋関数のテストで確かめる。
- 動作環境は README の前提条件（Claude Code 2.1.319、Windows 11）と同じ。
- 実装が済んだら、README の「機能」の表と、画像（`docs/panel.svg`）の説明を更新する。

## 8. 作り手に任せること

- 更新の間隔の細かい値、git・gh のコマンドの組み立て（6.1 の制約の範囲で）。
- 日時の表示形式（例: `11/05 11:40`）。
- 一覧のブランチ数が多いときの扱い（スクロールや省略）。
- 画面の記号・色の細部、幅の境目。

## 9. 作者に確認してほしい私の判断

| 判断 | 内容 |
|---|---|
| リリースを対象外にした | 段階は 8 つ。リリースは出さない |
| 1 人開発での「レビュー」 | reviewDecision が空なら「省略」とし、「今」は「マージ待ち」にする（自分の PR は承認できないため） |
| 「編集」の日時 | 未 commit の変更だけのときは「—」（変更ファイルの更新時刻は取らない） |
| 一覧の対象 | ローカルブランチだけ。origin にだけあるブランチは出さない |
| 狭い幅の並べ方 | 上に一覧、下に経過。幅があれば左右（作者が選んだ案は左右） |
| 更新間隔と対象 | git 10 秒、gh 60 秒。ブランチタブの表示中だけ更新する |
| `git fetch` をしない | origin の最新は、手元に取り込み済みの分だけを見る。鮮度を最終行に出す |
| マージ済み | PR が MERGED なら 1〜7 を済とし、「今」を削除にする |
| PR の採り方 | OPEN を優先。MERGED・CLOSED は、ローカルの先頭と一致または祖先のときだけ採る |
| 比較の基準 | 差分と commit 件数は `origin/<既定ブランチ>` と比べる |
| 未 commit の変更 | 未追跡のファイルも数える。マージ済みでも、未 commit があれば「今」は「編集中」 |
| 起動するプロセスの上限 | 1 回の更新でブランチごとに起動するのは 30 本まで。超えた分は「不明」 |
